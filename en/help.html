Help

When it won't work, narrow it down step by step.

Narrow it down in the order power → discovery → firewall → pairing → input & return. For Mac, the current public support path uses the same local Wi-Fi or LAN.

The return key below is the default. If you changed it in PC Settings → Shortcuts, use your saved key. If all shortcuts or emergency return are off on the main PC, return across the screen edge. See shortcuts and their conditions

Start with these two

  • Lost your cursor? → Press Ctrl+Alt+Backspace and the cursor returns to your own PC (center of the monitor).
  • Connected but input isn't working? → Re-enable OneMouse under Android Accessibility, or allow Accessibility for OneMouse on the Mac.

Troubleshooting order

Check one step at a time, in this order.

1

Power and permissions

Make sure OneMouse is running on Windows and on the target device. Android needs its Accessibility Service; a Mac receiving input from Windows needs Accessibility. Local Network appears on macOS 15+, while macOS 13/14 may not show it.

2

Same network & discovery

Check that Windows and the phone or Mac are on the same Wi-Fi or LAN. On macOS 15+, confirm OneMouse has Local Network access; on macOS 13/14, that settings item may not exist.

3

Firewall & isolation

If the phone can see the PC but the PC can't see the phone, it may be a Windows firewall inbound issue (whether the network is set to "Public" or "Private"). Office and café Wi-Fi can also block it with client isolation.

4

Pairing & connection

Confirm that pairing is finished and that the device shows as connected in Devices. For Mac, select the Mac in Windows and enter the 6-digit code displayed by the Mac. Before pairing, the input and file channels don't open.

5

Input & return

Push the mouse toward the arranged edge to see if it crosses over; if it doesn't, check the arrangement. If the cursor ends up somewhere odd, bring it back with Ctrl+Alt+Backspace.

Transfer

When files and clipboard won't go through.

  • Confirm the selected device is correct — a transfer goes to the target you selected.
  • Desktop-to-desktop drag requires the target Windows PC or Mac to be connected and arranged. Mac edge drag currently uses LAN.
  • Keep holding the file, cross the arranged screen edge, and drop it on the target to start the transfer.
  • If the clipboard doesn't come through, check that both apps are connected and whether a screen is off and idle.
  • Bluetooth is slower than Wi-Fi — send large files over Wi-Fi.

Phone notifications

When phone notifications don't show on the PC.

  • In the phone app's Notifications to PC settings, turn on Send notifications to PC and check that Notification access says allowed.
  • Check that the app is in Apps to send to PC. The defaults are your SMS app and KakaoTalk; you can also choose all apps.
  • On the main PC, open Settings → Notifications and make sure Device notifications is on.
  • If only verification-code messages arrive as "hidden", that is Android 15's protection. In the phone app's Verification-code notifications block, tap Register PC once. Bluetooth is only needed while registering.
  • Notifications appear briefly; history is encrypted locally on the PC, never uploaded. Only notifications received after enabling are recorded; verification codes and hidden sensitive content are not saved.
  • History defaults to on, 7 days, and up to 200 entries. Main-PC Settings → Notifications offers 1/7/30 days or no new entries. Existing history stays; Clear all deletes it.

Mac · Troubleshooting

Checks for the public macOS 13+ app.

Install the public Apple Silicon build and start the LAN connection from OneMouse on Windows.

The Mac does not appear in Windows Devices.
Put both computers on the same Wi-Fi or LAN. On macOS 15+, allow OneMouse under Privacy & Security → Local Network; macOS 13/14 may not show this item. Return to OneMouse and refresh Devices in Windows.
The Mac is connected, but mouse and keyboard input do not work.
Allow OneMouse under macOS Privacy & Security → Accessibility, then return to the app so it can recheck the permission. Basic input receiving does not require Input Monitoring.
The Mac screen is blank in the Windows remote-control window.
Allow OneMouse under macOS Privacy & Security → Screen & System Audio Recording. This optional feature is LAN-only and is not provided over Bluetooth; OneMouse does not capture system audio.
Can Windows and Mac connect over Bluetooth?
Yes, as a beta: enable Bluetooth in the Mac app settings (off by default). LAN remains the officially supported path. Mac screen and window sharing is LAN-only.
Where do I start a Mac connection?
Connections are started and managed from OneMouse on Windows 10/11. Select the Mac in Windows Devices and enter the 6-digit code shown on the Mac.

Frequently asked questions

The most common problems.

The Reply button is missing, or my reply will not send.

PC and Android need reply-capable versions and an original phone notification with free-text reply. Only live main-PC notifications qualify; hidden/sensitive content, verification codes, and history are excluded.

If sending fails, check the phone lock, deleted/expired notification, and connection. Failures and timeouts are not automatically resent; check the phone conversation. “Passed to phone app” confirms the original app's reply action, not delivery to the recipient. See how to reply

How do I change device numbers if Edit order is missing?

Edit order appears in main-PC Devices with two or more LAN devices. It saves automatically and updates connection/remote-window numbers, not screen arrangement or key combinations. Bluetooth order stays unchanged; sub-role PCs cannot edit. Change device order

Browser gestures do not work in a Windows remote window.

Use OneMouse for Windows 1.5.4 or later and enable the target browser's gesture extension or feature. The remote window forwards right-button drags, separately from Android's built-in gestures for direct phone control.

You can open remote windows for multiple devices; repeating a device's shortcut number brings its window forward. See the remote-window guide

A file shared from my phone does not reach the PC.

For Wi-Fi/LAN, choose a main-role Default PC on the phone's Home screen and check pairing/connection (sub PCs are excluded). An existing Bluetooth connection can send without a default PC. Send from phone to PC

I cannot change or open the PC's received-files folder.

On main or sub PCs, use Change/Open folder in Settings → General → File transfer → Received-file save location. For errors, check write access and USB/network drives or choose another accessible folder. Existing files stay put; screenshot saving is separate. See received-folder settings

The pointer does not return after capture, or the preview closes.

With supported versions on both sides, the pointer stays on the controlled device and only a separate preview appears; the main app stays in the tray or minimized. Copy/save success closes the preview; save cancellation or failure keeps it open. Move the pointer back to the main PC to use it. See screenshot results

Mouse gestures do not start.

Use supported PC/Android versions, enable Mouse gestures in Android Settings → Typing & clipboard, and select the current app (off by default). Move the pointer onto the phone, right-drag, then release; this does not apply to Windows/Mac or mirroring windows.

All apps covers installed apps with launcher icons and Home. OneMouse and system screens such as lock/permission dialogs are excluded; supported actions vary by app and screen.

View the gesture guide and all patterns

Forward or Reload does not work.
Forward returns to a page in browser history, not the next article. Reload needs a recognised native browser button; some selected apps or screens do not support it.
Does down → right close the app?
No. Draw down, then right as two strokes, not one diagonal. It goes to Home without closing the app, its tabs, or its recent-app card. Up → right opens the recent-app list so you can choose another app.
How do I adjust and stop up/down scrolling?

A longer up/down stroke scrolls more, a shorter one less; release the right button to start (nothing moves while drawing). The arrow and vertical gauge show direction and stroke strength, not document position or exact distance.

  • Start over page content. Very short, incomplete, or cancelled strokes do nothing; a short right-click without movement keeps its usual action.
  • Movement varies by app; Home/app drawer uses one swipe. Other long scrolls use several swipes, up to 8 screenfuls/10 seconds.
  • Clicking, a new gesture, switching apps, or ending control cancels remaining scrolling. Pointer movement alone does not stop it.
It keeps disconnecting about every 10 seconds.
There are four common causes: ① client isolation on guest/office Wi-Fi, ② battery optimization cutting off the phone's background connection, ③ Windows firewall inbound blocking, and ④ Wi-Fi going into power-saving (sleep) when the screen turns off. Turn on the battery exception, allow OneMouse inbound in the firewall, and use a private Wi-Fi when possible.
The phone can see the PC, but the PC can't see the phone.
This is usually a Windows firewall inbound issue. If the current network is set to "Public", inbound may be blocked, so switch it to "Private" or allow OneMouse inbound in the firewall.
It works at home but not on office or café Wi-Fi.
Public/guest Wi-Fi often isolates device-to-device communication (client isolation) for security. In that case, devices can't find each other even on the same Wi-Fi. Use a Bluetooth connection or a personal hotspot.
It says connected, but the mouse and keyboard don't respond.
The Android Accessibility Service was most likely turned off or restarted by the system. Go to Android Settings → Accessibility and re-enable OneMouse.
The cursor is stuck on the phone, another PC, or Mac and won't come back.
Press Ctrl+Alt+Backspace to force the cursor back to the center of your own PC's monitor.
The connection drops when the screen turns off.
When the screen turns off, the phone's Wi-Fi can go into power-saving or the app can go to sleep due to battery optimization. Setting OneMouse as a battery optimization exception on Android keeps it stable. Also check the keep-screen-on option while connected.
Remote screen control over Bluetooth doesn't work well.
Mobile remote screen control moves a lot of data, so it's not recommended over Bluetooth. Use Wi-Fi for remote control. Bluetooth is well suited to mouse, keyboard, clipboard, and files.
